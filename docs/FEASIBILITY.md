# 网维宝 · iOS 能力与可行性

这份文档区分三件事：**App 能做什么**、**iOS 允许做什么**、**网络工程上什么结论才算可信**。实现时会优先使用公开 API；不会用私有 API 换取功能，也不会把启发式结果包装成确定性结论。

## 总览

| # | 模块 | 可行性 | 推荐实现 | 主要限制 |
|---|------|--------|----------|----------|
| 1 | Ping | ✅ 可行 | `SOCK_DGRAM` + `IPPROTO_ICMP`，TaskGroup 并发 | 本地网络权限；目标可能丢 ICMP |
| 2 | DHCP 检测 | ✅ 已实现（待真机验证） | UDP 67/68 广播 DISCOVER/OFFER | 绑定 68、广播策略、企业网络隔离 |
| 3 | 路由追踪 | ✅ 已实现（受限） | 递增 TTL + 解析 ICMP 超时 | 无 raw socket；部分网络拿不到跳点 |
| 4 | 环路检测 | ✅ 已实现（启发式） | 广播重复回声 + 网关质量 | 读不到 MAC 表 / STP / 交换机端口 |
| 5 | 风暴检测 | ✅ 已实现（代理指标） | 广播前后链路质量对比 | 无 BPF / 混杂模式 / 端口镜像 |
| 6 | WiFi 分析 | ✅ 已实现（仅当前连接） | `NEHotspotNetwork` + 网关质量 | 不能扫描周边 AP；需定位权限与 entitlement |
| 7 | 子网计算 | ✅ 已实现 | 纯本地 IPv4/CIDR 计算 | 无 |
| 8 | 内外网测速 | ✅ 已实现 | LibreSpeed 后端（默认东京公共节点） | 公共节点可能限速；内网需自建后端；消耗流量 |

## 1. Ping

**已实现。**

- 使用非特权 ICMP datagram socket。Apple 的 SimplePing 也采用这一路径。
- 单机、CIDR 网段、批量三种模式。
- 并发受控，扫描可取消；超时、不可达、权限失败分别呈现。

**限制**

- 目标或中间防火墙可能丢弃 ICMP；超时不能证明主机离线。
- iOS 14+ 首次访问局域网会触发“本地网络”隐私提示。
- 当前未展示 TTL，因为 `SOCK_DGRAM` 返回的报文通常不带 IP 头；后续可通过 `IP_RECVTTL` / `recvmsg` 评估。

## 2. DHCP 服务器检测

**已实现**

- 发送只读 DHCPDISCOVER，收集并解析 DHCPOFFER。
- 同时发送到本网段广播和 `255.255.255.255`，最多等待 4 秒，按服务器标识去重。
- 展示服务器标识、分配地址、掩码、网关、DNS、租期、T1/T2、域名、广播地址、下一跳、启动文件、厂商类与厂商自定义选项。
- 不发送 REQUEST，不占用地址；只做发现。

**实现细节**

1. 优先绑定 UDP 68；失败时回退到临时端口，并在界面明确提示结果可能不完整。
2. 向 `255.255.255.255:67` 发送 DHCPDISCOVER，设置 broadcast flag，携带随机 xid、客户端 MAC、参数请求列表（1/3/6/51/54/58/59）。
3. 等待 DHCPOFFER，解析：
   - Option 53：消息类型
   - Option 54：DHCP Server Identifier
   - Option 51：租期
   - Option 1：子网掩码
   - Option 3：路由器
   - Option 6：DNS
   - Option 60 / 指纹特征：厂商识别
4. 展示服务器地址、租期、网关、DNS，以及多个 DHCP 服务器的冲突提示。

**风险**

- iOS 是否允许 App 绑定 68 端口需要真机验证；不同网络可能屏蔽广播。
- DHCPOFFER 通常广播或发往 68 端口，端口受限时可能收不到。
- 不能做 DHCP starvation / 欺骗类操作，只做只读发现。
- 企业网络可能启用 DHCP snooping、隔离或 Option 82，结果会受影响。

**备选**

- 若 68 绑定失败，尝试 DHCPINFORM（单播到候选服务器）或读取系统当前租约（iOS 不公开）。
- 最终可能只能显示“当前网段存在 DHCP 响应”，而不能完整读取租约。

## 3. 路由追踪

**已实现**

- 对 ICMP Echo 设置 `IP_TTL = 1...30`。
- 每跳等待 ICMP Time Exceeded、Echo Reply 或 Destination Unreachable，记录来源地址和 RTT。
- 到达目标时标记“目标”；无响应显示 `*`；不可达提前结束。
- 最大跳数、每跳超时可调，支持中途停止。
- 如果系统不暴露 ICMP 错误，会显示“路径不可见”警告，不伪造跳点。

**理论路径**

- 对 UDP 或 ICMP Echo 设置 `IP_TTL = 1...30`。
- 每跳等待 ICMP Time Exceeded，记录来源地址和 RTT。
- 到达目标时记录目标响应；无响应则显示 `*`。
- 支持并行探测、最大跳数、超时和 DNS 反查。

**关键不确定性**

iOS 不提供 raw socket。能否在非特权 socket 上稳定收到 ICMP Time Exceeded，必须在真机上验证；不同 iOS 版本和网络可能只返回有限错误。若拿不到跳点地址，不能伪造路径。

**降级方案**

- 只显示“路径长度”或“目标在第 N 跳内可达”，并明确标注为不完整。
- 对常见 TCP 端口做 TTL 探测，辅助判断路径长度；仍不保证跳点可见。
- 通过自建探针（见文末）获取完整 traceroute。

## 4. 环路检测

**已实现**

- 目标：开始检测时自动探测网段第一个/最后一个地址（常见 `.1` / `.254`），选择有响应的候选作为网关。
- 基线：对目标连续 Ping 8 次，记录丢包、平均延迟与抖动。
- 单播：向目标发送 10 个低强度 Echo，统计同源同序号重复回复。
- 广播：向 `255.255.255.255` 发送 8 个 Echo，补充广播复制证据。
- 复测：再次采样目标，比较探测前后的链路质量。
- 广播 ICMP 无响应时，只降低置信度，不直接判“无法判断”；结论仍可基于单播重复与链路质量。
- 输出“未发现明显迹象 / 疑似重复回声 / 无法判断”、采样证据与下一步建议。
- 明确标注为弱信号：Wi-Fi 重传、抓包镜像、重复 IP 都可能造成重复回复。

**不能做的**

- 读取交换机 MAC 地址表、STP 状态、端口镜像。
- 发送/分析 BPDU。
- 在 iPhone 上开启混杂模式。

因此该模块定位为**广播/链路级启发式排查**，真正定位二层环路仍需交换机侧命令或探针。

## 5. 网络风暴检测

**结论：公开 API 下无法抓包，因此无法做真正的风暴检测；已实现的是代理指标。**

真正的广播/组播风暴检测需要：

- 抓取链路层报文；
- 统计广播/组播包速率与来源；
- 可能还需要端口镜像或 SPAN。

iOS App 没有 BPF / promiscuous mode / raw Ethernet 权限，所以无法实现上述任一项。

**已实现的代理指标**

- 目标：自动探测 `.1` / `.254` 常见网关候选；
- 基线：对目标连续 Ping，建立丢包、延迟、抖动基线；
- 单播：向目标发送 10 个 Echo，统计重复回复；
- 广播：发送 8 个低强度广播 Echo；
- 复测：再次采样目标，比较探测前后的质量变化；
- 广播无响应时仍可依据单播与链路质量给出结论，并提示“广播级证据缺失”；
- 输出“未发现明显风暴征兆 / 疑似链路退化 / 无法判断”、采样证据与下一步建议。

若必须做真实风暴分析，建议采用**探针 + App 控制台**架构：探针接在交换机镜像口，App 通过局域网 API 读取统计。探针可以是 Raspberry Pi / OpenWrt 设备，使用 tcpdump/tshark。

## 6. WiFi 分析

**已实现**

- 读取当前 SSID、BSSID、是否加密、是否自动加入、信号强度。
- 对网关做 6 次采样，展示平均延迟、丢包与抖动。
- 请求“精确”定位权限；工程已加入 `com.apple.developer.networking.wifi-info` entitlement，并提供临时精确位置请求。
- 读取失败时仍显示 `en0` 接口、IP、网段、网关与链路质量，不伪造 SSID；模拟器通常返回空。
- 重新签名时，provisioning profile 也需要包含 WiFi Info entitlement。

**可用公开能力**

- `NEHotspotNetwork.fetchCurrent` 读取当前 SSID、BSSID、信号强度、安全类型、是否自动加入。
- 需要 **Access WiFi Information** entitlement（`com.apple.developer.networking.wifi-info`）。
- iOS 14+ 还需要定位权限（`NSLocationWhenInUseUsageDescription`）。
- 可结合网关 Ping、DNS 查询时延，给出无线链路质量评分。

**不可用**

- 扫描周边 AP 列表、信道占用、相邻 BSSID、RSSI 热图。
- 读取当前信道号（公开 API 不提供）。
- `NEHotspotHelper` 不是通用扫描接口，需要 Apple 单独授权，且面向热点辅助场景。

**产品表达**

- 叫“当前 WiFi 质量”而不是“WiFi 扫描”。
- 显示 SSID / BSSID / 信号强度 / 安全类型 / 网关延迟 / DNS 延迟。
- 注明“iOS 不提供周边 AP 扫描能力”。

## 7. 子网计算

**已实现 UI。** 支持 CIDR、`IP + 点分掩码`、单个 IP（/32），展示网络/广播/掩码/反掩码/主机范围/数量/二进制。纯本地计算，无权限要求。核心 `IPv4Subnet` 已随 Ping 模块完成：

- CIDR ↔ 网络地址 / 广播地址 / 掩码；
- 可用主机范围与数量；
- `/31`、`/32` 特殊处理；
- 网段大小上限保护。

后续只需补 UI，并可选加入 IPv6 前缀计算。

## 8. 内外网测速

**已实现**

- 外网默认节点：东京 A573 LibreSpeed（`https://librespeed.a573.net/backend`），已验证 10 MB 下载与 4 MB 上传。
- 内网：填写自建 LibreSpeed 后端的 `.../backend` 地址。
- 流程：5 次延迟采样 → 10 MB 下载 → 4 MB 上传。
- 结果：下载/上传 Mbps、平均延迟、抖动、丢包、传输字节、耗时；内网/外网结果可对比。
- 使用 Safari UA + Referer 访问 LibreSpeed 后端；公共节点可能限速或临时不可用。
- `NSAllowsLocalNetworking` 允许局域网 HTTP 测速；公网默认 HTTPS。

**可行路径**

- 下载：从指定 URL 读取固定大小/固定时长的数据，统计吞吐。
- 上传：向指定端点 POST/PUT 随机数据，统计吞吐。
- 延迟/抖动：小请求往返或与 Ping 结果结合。
- 内网：用户填写局域网测速服务地址（NAS / 自建 HTTP 服务）。
- 外网：用户配置或自建公网端点。

**注意**

- 公共测速服务（如 Ookla）通常有 API 授权与品牌使用限制，不应直接抓取。
- 需要处理 HTTPS 开销、缓存、CDN 选择、并发连接数；结果应标注测试条件。
- 移动网络测速会消耗流量，必须显式提示。

## 推荐交付路线

### 阶段一：App Store 安全范围（当前）

- Ping、子网计算、当前 WiFi 质量、自建端点测速。
- DHCP 只读发现、traceroute 尽力而为。
- 所有受限能力在 UI 中写明边界。

### 阶段二：探针联动

为环路、风暴、周边 AP 扫描增加一个可选探针：

- 探针：Raspberry Pi / OpenWrt，接镜像口或管理口。
- App 通过局域网 HTTPS/配对码连接探针，读取 pcap 统计、STP/MAC 表、AP 扫描结果。
- App 仍然保持 App Store 合规，探针承担需要特权的采集。

### 阶段三：专业版

- 报告导出、历史对比、多人协作。
- 企业分发 / MDM 场景下的定制能力。
- 仍然不建议使用私有 API；企业签名也不能绕过内核权限。

---

## 明确不做

- 不使用私有 API、越狱、动态注入。
- 不伪造 traceroute 跳点、风暴结论或 WiFi 扫描结果。
- 不做 DHCP 欺骗、ARP 欺骗、deauth 等攻击性功能。
- 不把“超时”直接等同于“设备离线”。
